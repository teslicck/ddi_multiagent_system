# CLAUDE.md — DDI Agents

Сводка задачи для Claude Code. Читать перед любой работой в репозитории.

## Задача (учебный проект)

Курсовое задание: **мультиагентное приложение для сбора информации из внешних источников**.
Требования преподавателя:
- работает ровно с **2 источниками** из реестра курса (`Источники.pdf`, реестр медицинских источников);
- обёрнуто в **web-интерфейс** (Streamlit) и **выложено в web** (Streamlit Community Cloud);
- к семинару нужны доклад и презентация (архитектура, взаимодействие агентов, демо, ограничения).

**Тема:** взаимодействие лекарств (drug-drug interaction, DDI). Пользователь вводит два препарата
и получает сводку о взаимодействии со ссылками на источники.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Источник 1 | **DailyMed** REST API (инструкции FDA, раздел 7 «Drug Interactions») | есть в реестре, бесплатно, без ключа |
| Источник 2 | **PubMed** через NCBI E-utilities | есть в реестре, бесплатно, ключ необязателен |
| LLM | **Groq**, `openai/gpt-oss-120b` (`reasoning_effort: low`); экономный вариант — `qwen/qwen3.8-27b`; запасной провайдер — OpenRouter `:free` | у автора нет платных ключей; `llama-3.3-70b-versatile` Groq убрал (404 `model_not_found`, ноябрь 2026) |
| Вызов LLM | OpenAI-совместимый `/chat/completions` через `requests`, без SDK | провайдер меняется одной строкой в секретах |
| UI / хостинг | Streamlit → Streamlit Community Cloud | проще всего для учебного проекта |

**Не использовать:** RxNav Interaction API (`rxnav.nlm.nih.gov/REST/interaction/...`) отключён
2 января 2024 года, эндпоинты больше не работают. Остальной RxNorm работает, его можно взять
как вспомогательный шаг нормализации названий (бренд → действующее вещество), но это не
третий «источник» без согласования с преподавателем. DrugBank не брать: сложная лицензия.
DDInter 2.0 есть только как идея на будущее (нет в реестре, нет документированного API).

## Архитектура

```
Streamlit (app.py, кэш st.cache_data на сутки)
   └─ orchestrator.run(drug_a, drug_b)
        ├─ rxnorm.normalize ×2 → действующее вещество; стоп, если не распознано / комбинация / одно и то же
        ├─ dailymed_agent ─┐  параллельно (ThreadPoolExecutor); каждый: клиент → ref → LLM-сводка
        ├─ pubmed_agent  ──┘  → SourceReport (evidence + summary + errors)
        ├─ synthesizer   → ответ по сводкам, каждое утверждение со ссылкой [DM1] / [PMID:123]
        └─ critic        → формальная проверка ссылок + LLM (другая модель) сверяет с фрагментами
```

**LLM-бюджет:** не больше 4 вызовов на запрос (2 сводки, синтезатор, критик). Без evidence
LLM не вызывается: ответ «не найдено» детерминированный, и критик его тоже не проверяет.
Сводки и синтезатор идут на `gpt-oss-120b`, критик на `qwen/qwen3.8-27b` (`LLM_CRITIC_MODEL`):
у Groq лимит 8 000 токенов в минуту **на модель**, так что критик не делит его с остальными,
а заодно это независимая проверка другой моделью.

**Ссылки:** `Evidence.ref` — `DM1`, `DM2`… для фрагментов DailyMed, `PMID:<id>` для статей.
UI превращает их в ссылки на источник. Критик не переписывает ответ, а показывает замечания.

**Нормализация (RxNorm, вспомогательный шаг, не источник):** `ddi/sources/rxnorm.py`.
Точное совпадение `rxcui.json?search=2` → иначе `approximateTerm` (опечатки, показывается
предупреждение) → `related.json?tty=IN` (действующие вещества). Статусы `DrugName.status`:
`exact`, `approximate`, `combination` (>1 вещества, стоп), `not_found` (в т.ч. устаревшие
понятия вроде Vicodin, стоп), `unavailable` (RxNav недоступен → ищем как введено, с предупреждением).
Нераспознанное название **никогда** не превращается в «в источниках не найдено».
Бонус: paracetamol → acetaminophen (DailyMed и PubMed американские). ~3,5 с на название,
оба названия параллельно.

**Классы препаратов (RxClass, вспомогательный шаг):** `ddi/sources/rxclass.py`. Для
действующего вещества берутся классы FDA (`relaSource=FDASPL`, EPC и MoA): это те же классы,
что FDA ставит в инструкциях, поэтому их формулировки совпадают с текстом инструкций.
Из них строятся термины поиска: единственное число («cytochrome p450 3a4 inhibitor»),
`cyp3a4 inhibitor`, сокращения из `CLASS_ALIASES` (NSAID, SSRI, SNRI, ACE inhibitor, statin…),
`serotonergic` для любого класса с серотонином. ATC и VA не берём: там классы комбинированных
препаратов (ибупрофен попадает в «Opioid analgesics»). Слишком общие фразы — в `TOO_BROAD`.
Совпадение по имени ранжируется выше, чем по классу; у фрагмента `meta["match"] = "class"`,
и LLM прямо сообщается, что препарат во фрагменте не назван. Если RxClass не ответил
(1 повтор, таймаут 10 с), `DrugName.class_error` и предупреждение в UI. Ручной `RELATED_TERMS`
остался как дополнение (то, чего нет в RxClass: «strong cyp3a4 inhibitor», «anticoagulant»).

Результат на живых данных (до → после): meloxicam + lisinopril — найдено направление
«инструкция lisinopril про NSAIDs»; escitalopram + tramadol — «инструкция tramadol про
serotonergic drugs»; sertraline + tramadol — новый фрагмент «Inhibitors of CYP2D6» в
инструкции tramadol; metformin + amoxicillin — по-прежнему 0 (шума не добавилось).
RxNav иногда отвечает медленно (1,5–24 с на тот же запрос) и бывают сбои DNS.

**Защита от переноса «чужой» силы действия** (`_potency_qualified_class_match`): совпадение
только по классу внутри группы со словами strong / moderate / weak / potent отбрасывается.
Живой случай: инструкция simvastatin, группа «Strong CYP3A4 inhibitors» (примеры:
itraconazole, ketoconazole…) нашлась для fluconazole по классу «azole»; агент назвал
флуконазол сильным ингибитором, синтезатор перенёс «противопоказано». Критик это поймал,
но правило в промпте агент проигнорировал, поэтому защита сделана детерминированной.
Совпадения по имени и ручные термины, в которых сила указана («strong cyp3a4 inhibitor»),
не отбрасываются. Цена: теряется фрагмент, если препарат умеренный и не назван в группе
«moderate …» — для медицинского домена лучше пропуск, чем ложная рекомендация.

**Ссылки от gpt-oss:** модель иногда пишет `【DM1】` вместо `[DM1]`; `normalize_citations`
приводит такие скобки к обычным после каждого вызова LLM.

**Агент «НЕ НАЙДЕНО»:** если фрагменты есть, но не о той паре, сводка агента — `НЕ НАЙДЕНО`;
если так ответили все агенты с evidence, синтезатор выдаёт детерминированное «не найдено».

Модели данных в `ddi/models.py`: `Evidence` → `SourceReport` → `FinalReport`.
Клиенты в `ddi/sources/` не вызывают LLM, это чистый HTTP и парсинг. Логика LLM живёт в `ddi/agents/`.

## Структура

```
app.py                     Streamlit UI (готов, рисует FinalReport)
ddi/config.py              Settings: st.secrets → env → .env
ddi/models.py              pydantic-модели
ddi/llm.py                 complete(system, user): groq|openrouter|gemini|ollama, ретраи на 429
ddi/sources/dailymed.py    готов: find_interactions(a, b) → (evidence, errors), поиск в обе стороны
ddi/sources/rxnorm.py      нормализация названий: normalize(name) → DrugName (+ классы)
ddi/sources/rxclass.py     классы FDA из RxClass → термины поиска для инструкций
ddi/sources/pubmed.py      готов: find_interactions(a, b) → (evidence, errors), ранжирование статей
ddi/agents/common.py       ref-ы, разбор ссылок, сборка evidence в промпт, формальные проверки
ddi/agents/retrievers.py   агенты: клиент → ref → LLM-сводка своего источника
ddi/agents/synthesizer.py  итоговый ответ по сводкам; фолбэк без LLM
ddi/agents/critic.py       проверка ответа: формальная + LLM на отдельной модели
ddi/agents/orchestrator.py готов
tests/test_smoke.py        прогон пайплайна без сети
tests/test_dailymed.py     клиент DailyMed на урезанных реальных ответах (tests/fixtures/dailymed/)
tests/test_pubmed.py       клиент PubMed на урезанных реальных ответах (tests/fixtures/pubmed/)
tests/test_agents.py       агенты с подставным LLM (FakeLLM), включая бюджет вызовов
tests/test_rxnorm.py       нормализация на сохранённых ответах RxNav (tests/fixtures/rxnorm/)
tests/test_rxclass.py      термины классов на сохранённых ответах RxClass (tests/fixtures/rxclass/)
```

## Особенности DailyMed (выяснено на живых данных)

- Без фильтра поиск возвращает в основном OTC-инструкции («Drug Facts»), где нет раздела
  Drug Interactions. Поэтому ищем только рецептурные: `doctype=34391-3`.
- LOINC `34073-7` ненадёжен: в старых инструкциях им бывает помечен посторонний раздел
  («Preexisting asthma»), а настоящий «Drug Interactions» помечен как unclassified.
  Раздел ищем по коду **или** по заголовку, «Drug/Laboratory Test Interactions» пропускаем.
- Название препарата часто есть только в заголовке подраздела («Warfarin-type anticoagulants»),
  поэтому фильтр смотрит и на заголовок, и на текст.
- Таблицы нового формата состоят из групп: строка-заголовок («Strong CYP3A4 inhibitors»), затем
  «Clinical Impact / Intervention / Examples». Группа идёт одним фрагментом.
- Таблицы бывают на тысячи символов: окно в 1 500 символов строится вокруг упоминания препарата.
- Классы и синонимы (NSAID, SSRI, strong CYP3A4 inhibitor…) лежат в `RELATED_TERMS`. Список
  неполный: остальные препараты ищутся только по названию (ограничение для доклада).
- У инструкций нового формата заголовок документа — дисклеймер «These highlights…», поэтому
  название берётся из результатов поиска.

## Особенности PubMed (выяснено на живых данных)

- Запрос: `<a>[tiab] AND <b>[tiab] AND (drug interactions[mh] OR interaction[tiab])`, `sort=relevance`,
  10 PMID → один `efetch`. Передаются `tool=ddi-agents`, а также `email` и `api_key`, если заданы.
  Пауза между запросами: 0,34 с без ключа, 0,11 с с ключом (общая блокировка на процесс).
- Сортировка по релевантности поднимает общие обзоры, где пара упомянута вскользь, а
  статьи по связыванию с альбумином используют warfarin и ibuprofen как «маркеры мест связывания».
  Поэтому статьи переранжируются локально (`score_article`): 3 — оба препарата в заголовке;
  2 — оба в одном предложении аннотации со словом про взаимодействие или эффект; 1 — просто
  совместное упоминание или биофизическая статья; 0 — препараты в разных предложениях.
  В evidence попадают только статьи с оценкой ≥ 2 (`MIN_SCORE`), до 5 штук.
- Длинные аннотации сокращаются до 1 500 символов: сначала предложения с обоими препаратами,
  потом вывод, потом предложения с одним из них; пропуски помечаются «…».
- Статьи без аннотации остаются, только если оба препарата есть в заголовке (тогда текст = заголовок).
- Для пары без известного взаимодействия (metformin + amoxicillin) PubMed всё равно может отдать
  1 статью о совместном приёме. Решать, есть ли там взаимодействие, должен синтезатор, а не клиент.

## Результаты живой проверки (ноябрь 2026, пригодится для доклада)

- Критик находит реальные неточности синтезатора: «удлиняет протромбиновое время», хотя
  инструкция FDA пишет обратное (warfarin + ibuprofen); «полностью прекратить» вместо
  «приостановить на время курса» (simvastatin + clarithromycin); «рассмотреть прекращение»,
  хотя инструкция трамадола требует прекратить немедленно (sertraline + tramadol).
- metformin + amoxicillin: PubMed нашёл 1 статью о совместном приёме, агент прочитал её
  и ответил «НЕ НАЙДЕНО», итог — «не найдено» (1 LLM-вызов).
- Известная мелочь: `gpt-oss-120b` иногда пишет «тррамадол» с опечаткой.
- Возможное улучшение (вне бюджета 4 вызовов): второй проход синтезатора с замечаниями критика.

## Ограничения и правила

- **Лимиты Groq на бесплатном тарифе** (порядка 10 000 токенов в минуту, точные цифры по модели
  смотреть в console.groq.com). У `gpt-oss-120b` скрытые рассуждения тоже расходуют `max_tokens`. Обрезать evidence: топ-N фрагментов,
  примерно 1 500 символов на фрагмент. Не больше 4 вызовов LLM на один запрос пользователя.
- **Секреты:** только через `st.secrets` или `.env`. `.streamlit/secrets.toml` и `.env` в `.gitignore`,
  никогда не коммитить. Шаблон лежит в `.streamlit/secrets.toml.example`.
- Модель не должна выдумывать взаимодействия: если в evidence ничего нет, ответ должен быть
  «в источниках не найдено», а не «взаимодействия нет».
- В UI всегда показывать дисклеймер: справочный инструмент, не медицинская консультация.
- Названия препаратов вводятся на английском (DailyMed и PubMed англоязычные): МНН, соль или
  торговое название; RxNorm сводит их к действующему веществу.
- Тесты не должны ходить в сеть: мокать `requests` или использовать фикстуры с сохранёнными ответами.
- Язык интерфейса и ответов русский, код и комментарии на английском.
