# DDI Agents

Мультиагентное приложение: собирает информацию о взаимодействии двух лекарств
из **DailyMed** (инструкции FDA: Boxed Warning, Contraindications, Drug Interactions) и **PubMed**
(научные статьи), сводит её в ответ со ссылками и проверяет агентом-критиком.

**Демо:** https://ddimultiagentsystemdaniiln.streamlit.app/

> Справочный инструмент, не медицинская консультация.

## Практическая работа № 2 · Клинические инструменты MCP

Из корня репозитория с Python 3.11/3.12 запустите `python start.py` (в Windows также
подойдёт `py -3.12 start.py`). Скрипт создаёт локальное окружение, устанавливает зависимости,
запускает SSE-сервис на порту 8000 и выводит локальный адрес Streamlit. Остановка — Ctrl+C.
Перейдите на страницу **Клинические инструменты MCP** в боковом меню. Для неё ключ LLM не требуется.

| Источник | Что показать на защите |
|---|---|
| Локальный stdio | Выберите ИМТ, включите учебный пример и вызовите инструмент. Для 70 кг и 175 см результат равен 22,86 кг/м². Откройте инспектор и сопоставьте идентификаторы запроса и ответа. |
| Локальный SSE | Выберите qSOFA. В учебном примере ЧДД 22/мин и САД 100 мм рт. ст. дают по одному баллу, суммарно 2 из 3. |
| Внешний PubMed | Выберите поиск статей, введите `warfarin AND ibuprofen`, выполните запрос и раскройте ответ сервера. Повторный успешный запрос доступен из кэша той же сессии 15 минут. |

Клиент выполняет `initialize`, сообщает о готовности и вызывает `tools/list` или
`tools/call` через SDK MCP 2.3.0. Для stdio приложение само создаёт процесс
`python -m clinical_mcp.server`. В сетевом варианте самостоятельный процесс
`python -m clinical_mcp.server --sse` принимает SSE на `/sse` и JSON-RPC POST на
`/messages/` с идентификатором сессии. Команды можно запускать отдельно из активированного окружения.
При запуске только `streamlit run app.py` для работы сетевого источника нужен этот второй процесс.
Для Cursor откройте корень репозитория из среды, в которой команда `python` видит установленные зависимости.
Конфигурация подключения находится в `.cursor/mcp.json`.

Через stdio доступны ИМТ, Cockcroft–Gault, GCS и справочник `list_calculators`.
Сетевой каталог дополнительно содержит Mosteller BSA и qSOFA. Справочник публикует схемы
с единицами и границами ввода. Учебный пример заполняет поля по явному выбору пользователя.
Публичный источник использует [коннектор PubMed](https://claude.com/connectors/pubmed)
по Streamable HTTP. Адрес можно задать переменной `PUBMED_MCP_URL` для совместимого сервера.
Для внешних запросов установлен предел ожидания 15 секунд. Инспектор показывает сообщения
того обмена, из которого получен результат, включая ответы с ошибками.

### К защите

- **Как агент узнаёт, что можно вызвать?** После согласования версии клиент получает имена и
  JSON-схемы инструментов через `tools/list`. Для вызова любого из них используется
  одна операция `tools/call`. В REST API операции обычно привязаны к собственным HTTP-маршрутам.
- **Куда идут логи?** При stdio канал stdout занят протоколом. Одна посторонняя строка
  может нарушить разбор JSON. Диагностика процесса направляется в stderr.
- **Как проследить запрос?** В `initialize` клиент передаёт версию, возможности и сведения
  о себе. После ответа он отправляет `notifications/initialized`. У `tools/call` поле
  `params` содержит имя и аргументы. Ответ с тем же `id` содержит `result` либо `error`.
  Ошибка самого инструмента может находиться внутри `result` с признаком `isError`.
- **Зачем SSE?** Один сетевой сервис обслуживает несколько сессий и живёт отдельно от интерфейса.
  Клиенту нужны доступный порт, таймауты и обработка разрыва соединения. В stdio каждый клиент
  управляет своим дочерним процессом.
- **Как проверяются параметры?** Формулы детерминированы, параметры типизированы и ограничены
  на сервере. Интерфейс показывает единицы. Правдоподобное, но ошибочное измерение пройдёт
  такую валидацию, поэтому исходные данные нужно сверять с записью пациента.

## Архитектура

```
Пользователь (Streamlit)
        │
   Нормализация названий (RxNorm: Advil → ibuprofen, опечатки, комбинации)
   + классы FDA (RxClass: meloxicam → NSAID, чтобы найти «NSAIDs» в инструкциях)
        │
   Оркестратор ──┬── DailyMed-агент ── DailyMed REST API  ─┐ параллельно,
                 └── PubMed-агент  ── NCBI E-utilities    ─┘ каждый с LLM-сводкой
        │
   Синтезатор (LLM) → Критик (другая LLM) → Редактор (исправляет по замечаниям)
        → повторная проверка → ответ со ссылками [DM1] / [PMID:…]
```

LLM: Groq (`openai/gpt-oss-120b`, критик — `qwen/qwen3.8-27b`), до 6 вызовов на запрос.

## Структура

```
app.py                  Streamlit-интерфейс
ddi/config.py           настройки (st.secrets → env → .env)
ddi/models.py           Evidence, SourceReport, FinalReport
ddi/llm.py              обёртка над LLM (OpenAI-совместимый API: Groq / OpenRouter / Gemini / Ollama)
ddi/sources/            клиенты DailyMed и PubMed (без LLM)
ddi/agents/             retrievers, synthesizer, critic, orchestrator
tests/                  тесты
```

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # заполнить ключи
streamlit run app.py
pytest
```

## Оценка качества

`eval/` — эталонный набор из 40 пар (30 известных взаимодействий, 10 без) и скрипт оценки:

| Метрика | Значение |
|---|---|
| Поиск без LLM: взаимодействие найдено хотя бы в одном источнике | 30/30 |
| Полный конвейер: ответ сообщает о взаимодействии (выборка 10) | 10/10 |
| Ложные заявления о взаимодействии (10 пар без него) | 0/10 |
| Замечаний критика на ответ до → после исправления | 1,0 → 0,2 |

Подробности и разбор спорных случаев — `eval/README.md`.

## Деплой (Streamlit Community Cloud)

1. Запушить репозиторий на GitHub (без `secrets.toml`).
2. share.streamlit.io → New app → репозиторий, ветка `main`, файл `app.py`, Python 3.12.
3. Advanced settings → Secrets: достаточно двух строк
   ```toml
   LLM_PROVIDER = "groq"
   LLM_API_KEY = "gsk_..."
   ```
   Модели подставляются по умолчанию, ключ NCBI необязателен.

Каждый пуш в `main` пересобирает приложение автоматически. Приложение публичное:
все запросы тратят лимит одного ключа Groq (8 000 токенов в минуту на модель);
повторные запросы той же пары берутся из кэша на сутки.
